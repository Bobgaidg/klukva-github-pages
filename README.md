# KLUKVA — демонстрация для GitHub Pages

Готовая статическая копия основной версии `Site/Витрина`. Сборка, npm и отдельный сервер для публикации не нужны.

**Инструкция Word:** [Как опубликовать сайт на GitHub Pages](<instructions/Инструкция — публикация на GitHub Pages.docx>).

## Как опубликовать через браузер

1. Создайте на GitHub публичный репозиторий `klukva-github-pages`, включив **Add README**.
2. Откройте **Add file → Upload files** и перетащите **содержимое** этой папки, сохранив папки `assets`, `css`, `js`, `data`, `tools` и `instructions`. Папку `.git` не загружайте. `index.html` должен оказаться прямо в корне репозитория.
3. Сохраните загрузку в `main` через **Commit changes** (если GitHub предлагает запрос на слияние, завершите его в `main`).
4. Если скрытый `.nojekyll` не загрузился: **Add file → Create new file**, имя `.nojekyll`, содержимое `# Static site`, сохранить в `main`.
5. В **Settings → Pages** выберите **Deploy from a branch → main → /(root) → Save**.
6. Откройте адрес из **Settings → Pages → Visit site**. Обычно это `https://ВАШ-ЛОГИН.github.io/klukva-github-pages/`.

Ссылка `github.com/ЛОГИН/РЕПОЗИТОРИЙ` ведёт к файлам. Для просмотра сайта отправляйте ссылку с `github.io`. Архив ZIP сначала распакуйте: загрузка одного ZIP не публикует сайт.

## Что работает

- Главная страница, каталог, поиск, категории, сортировка и страницы каталога.
- Карточки товаров, страницы брендов и просмотр изображений.
- Светлая и тёмная темы, последние просмотренные товары в текущем браузере.
- Страницы условий, политик и пояснение демонстрационного режима.

## Данные и ограничения

В копии 126 опубликованных тестовых карточек, 6 вымышленных брендов и 8 разделов. Черновики не экспортированы. Состояние зафиксировано при подготовке 30.10.2026 и не синхронизируется с исходным сайтом.

Внешние и сломанные тестовые изображения заменены локальными SVG-заглушками; несуществующие ссылки тестовых поставщиков отключены. Дизайн и исходные тексты витрины сохранены, добавлена подпись о демонстрации.

Вход поставщиков, админка, создание и изменение товаров, модерация, обработка подписок и общая база требуют отдельного сервера. Их здесь нет. Форма заявки показывает интерфейс и ничего не отправляет. Аналитика не подключена; личные настройки хранятся в localStorage.

Пароли, `.env`, данные учётных записей, журналы, исходная админка и рабочие документы проекта в этот репозиторий не копировались. Содержимое публичного репозитория, включая инструкцию, будет доступно всем.

## Локальный просмотр

При установленном Node.js откройте `Preview.cmd` или выполните из этой папки:

```sh
node tools/preview.mjs
```

Откройте `http://127.0.0.1:4173/klukva-github-pages/`. Остановить сервер: Ctrl+C. На GitHub Pages Node.js устанавливать не требуется. Открытие `index.html` как локального файла не загружает JSON-каталог.

## Как обновлять каталог

Публичные данные находятся в `data/products.json`, `data/brands.json`, `data/categories.json`. После правок загрузите изменённые файлы в `main`, сохранив пути. Для новой карточки нужны уникальный `id`, существующий `supplierId`, название, бренд и массив `categories` с ID разделов. Полный пример полей есть в существующих карточках. Все записи `products.json` доступны посетителям; статический сайт не обрабатывает статусы черновиков или даты подписок. Фотографии находятся в `assets/images`, путь в JSON указывается от корня сайта, например `assets/images/ceramics.svg`.

При добавлении реальных данных отдельно проверьте права на тексты и фотографии. Юридические страницы в этой демонстрации содержат исходные макеты.
